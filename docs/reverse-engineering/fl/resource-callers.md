# Farnham's Legacy resource callers

Static caller-policy reconstruction, 2026-10-27, for fog and LOD regeneration.
The supported image is FL `X3FL.exe`, SHA-256
`e7f3aad8d728e021f589c76591a35d8bf47eb170e4f7164f6b26f1ff401dfbb8`,
PE32 x86, preferred base `0x400000`. Addresses below are preferred-image VAs;
this is not a hook profile or runtime qualification.

The [reviewed resolver](resource-resolver.md) supplies the shared
contract: root then addon2 mounts, ordered selected mods, preserved member
namespaces, extension-aware loose-first selection and exact-open catalog-first
selection. **There is no inferred global addon2/addon/root fallback.** A physical
catalog's directory does not change its members' keys. This note establishes
which requests selected callers actually make.

## Caller policies

| Caller | Requested key / accepted extensions | Reader and qualified behavior |
| --- | --- | --- |
| Body `0x4a1a40` | `objects\<body-name>`; `pbb bob pbd bod` | Buffer owner `0x506d30`, hence extension open `0x505e00`, game-directory flag zero. On selected-resource failure, records failed body and returns; no alternate namespace retry. |
| Scene `0x4aeaf0` | `objects\<scene-name>`; `pbb bob pbd bod` | Same extension reader; failure records failed scene and returns. Scene uses the same extension list as body, not a guessed scene-only list. |
| Types category 2 | `addon2\types\TBackgrounds`; `pck txt` | `0x44056b -> 0x487d40 -> 0x506d30`; extension-aware loose-first. |
| Background geometry generated by category 2 | Body names under `environments\nebulae\<family>\nebula_<family>...` | Registers body IDs through `0x486c60`; the body reader supplies the `objects\` prefix and body extension list. |
| Texture dispatcher `0x510890` | Caller-specific ordered attempts described below | DDS wrapper accepts `pck dds`, TGA `tga`, JPG `jpg`; each calls `0x505e00` with flag zero. |
| Effect `0x4db2c0` | `shader\<profile>\<effect-name>`; `fb` | `0x505e00`, flag zero, then `0x505f40`; feeds `D3DXCreateEffect`. |

Within an extension-aware attempt, loose-resource precedence is above archive
precedence, and a later catalog containing an accepted extension wins before
ranking extensions in lower catalogs. This is **not** a single flattened
extension-first search across all packages. Localized-versus-unlocalized ties
remain the resolver note's explicit blocker; this caller audit does not resolve
them. Failed selected payload reads do not imply retrying lower catalogs.

## Bodies and scenes: names, formats and failure boundaries

`0x4a1aca` calls body-name getter `0x4867b0` with `(result, id, 1)`.
The body manager is `*(0x5aa100)`: counts `+0xb4/+0xb8`, table `+0xbc`,
record stride `0x1c`, name pointer `+0xc`. ID-to-slot mapping is id below 1000,
id minus 9000 below 20000, otherwise id minus 20000 plus count `+0xb4`;
negative/out-of-range slots return an empty string. A valid unnamed slot uses
`v\%05d` at `0x58ca80`, selected by `0x486826` and formatted at `0x486833`.
Registered names are copied by `0x4866e0` into the same `+0xc` field
(`0x486793..0x4867a2`). `0x486c60` searches that table, registers a missing
name, and returns the corresponding body ID; dynamic IDs start at 20000.
The table may be reallocated at `0x486dc9/0x486dd9`.

`0x4aeba3` similarly calls scene-name getter `0x486af0` with `(result, id, 1)`.
Its table is manager `+0xc8`, stride 8, name at offset zero; counts are
`+0xc0/+0xc4`. IDs at least 50000 map to id minus 50000 plus `+0xc0`.
A valid unnamed slot formats `cut\%05d` (`0x58ca88`, call `0x486b58`).
These numeric mappings are bounded by the tables; they do not authorize a
regenerator to fabricate arbitrary missing numeric resources.

The separate empty-getter fallback strings are literally `v\%05` at
`0x58cbdc` and `cut\%05` at `0x58ccbc`, passed to formatters at
`0x4a1ae4/0x4aebbc`. They lack the final `d` present in normal numeric-name
formats. Their malformed-format behavior is **not qualified**. Regeneration
should reject invalid IDs/empty names with a reason, rather than silently
normalizing that exceptional branch to the normal format.

Both loaders format descriptor `+0x1c = objects\%s`
(`0x4a1b4b/0x4a1b50`, `0x4aec1f/0x4aec26`), then pass extension string
`0x58cbf8` to the buffer constructor (`0x4a1bb9`, `0x4aecc5`). Failure byte
owner `+0x24` branches to cleanup/failed-ID registration
(`0x4a1bf0..0x4a1c08`, `0x4aed09..0x4aed20`). No second resource request
occurs on these failure paths.

Parser selection examines payload bytes, not the chosen filename extension:
body compares the first three bytes to `BOB` (`0x4a1c0d..0x4a1c26`), calling
binary parser `0x49ae00` at `0x4a1ca2`, otherwise text parser `0x49db00` at
`0x4a1d24`. Scene compares `CUT` (`0x4aed9e..0x4aedb5`), calling binary parser
`0x4acf60` at `0x4aee1f`, otherwise text parser `0x4adb90` at `0x4aee8e`.
This establishes the reader/dispatch contract, not complete parser validity,
packed-payload decompression, or malformed-buffer safety.

## TBackgrounds connects fog inputs to body resources

Category dispatch at `0x44045a` uses `0x442a9c`; element 2 is `0x44046d`,
which supplies `TBackgrounds` (`0x588590`) and joins the common types-reader
call at `0x44056b`. The row-parser dispatch at `0x44073d/0x440744` uses byte
`0x442b62 = 1` and pointer `0x442b20 = 0x4409b4`. This links the table name to
the geometry-name builder, rather than relying on nearby strings.

The parser copies the family string to row `+0x44` (`0x4409bd..0x4409e9`),
then constructs `environments\nebulae\` + family + `\nebula_` + family at
`0x440b51..0x440ba0`. Each loop appends a literal suffix and a one-based
`%02d` index, then calls body registration `0x486c60`:

| Suffix | Count and stored IDs | Registration / loop witness |
| --- | --- | --- |
| `_stars_` | Row `+0x48`; IDs at `+0x4c` | `0x440c3e`, back edge `0x440c69 -> 0x440bf2` |
| `_background_` | Row `+0x8c`; IDs at `+0x90` | `0x440cec`, back edge `0x440d1a -> 0x440ca0` |
| `_outside_part` | Row `+0xd0`; IDs at `+0xd4` | `0x440d9e`, back edge `0x440dcc -> 0x440d52` |
| `_dust_part` | Exactly eight; IDs at `+0xf4` | `0x440e4c`, compare 8 at `0x440e70`, back edge `0x440e73 -> 0x440e00` |

Stars/background counts outside 1..16 are replaced by 16
(`0x4409f4..0x440a1c`). For table version at least 25, outside count is read
and values outside 1..8 are replaced by 8; older versions use 1
(`0x440a26..0x440a4f`). Thus a dust request has the concrete form
`objects\environments\nebulae\<family>\nebula_<family>_dust_part01` through
`...08`, accepted extensions `pbb bob pbd bod`, through the body policy above.
These are body registrations, not scene-file requests.

The parser also fills `+0x114..+0x15c`, including version-dependent fields.
This audit does **not** assign semantic fog-density/distance names to those
fields or establish every map/sector selector that chooses a background row.
Other runtime background setters and script-driven changes remain outside this
bounded trace. The base table and generated geometry paths are established.

A nearby apparent competing path is a **writer**: `0x44308b/0x443096` formats
`TBackgrounds` with descriptor `+0xac = addon2\types\%s.txt`, then calls
`0x506c70` at `0x443117`. That constructor passes `wb` (`0x58bb78`) to exact
open `0x5063c0` at `0x506cb5`. It does not establish catalog-first reading of
TBackgrounds, nor a root-types fallback.

## Texture names and ordered attempts

Within the reviewed table-backed texture branch `0x5115bb..0x5116b0`:

- A named record normally formats descriptor `+0x78 = textures\%s`.
  Flag `0x10000000` selects `%s` instead (`0x51160d..0x511627`), preserving
  the supplied name without that prefix.
- The high-index name branch uses `%s_l` (`0x591400`, call `0x511602`).
  The earlier font-scale/flag branch can add 10000 (`0x5115bb..0x5115d1`);
  config +0x774 is `-fontscale`, not texture quality (see the
  [LOD texture audit](lod-textures.md)).
- An unnamed record formats `true\%d` then descriptor `+0x74 = tex\%s`
  (`0x51162d..0x51164f`). All three paths call `0x510890` at `0x511687`.
  Special procedural/global texture branches preceding this window are not
  treated as ordinary file requests.

`0x510890` receives a C-string name in ECX and flags in EDX. For an explicit
`.jpg` or `.tga` suffix, it first calls that format's reader
(`0x5108ed`, `0x510973`). A null result removes the four-character suffix and
recursively calls this dispatcher (`0x51092f/0x510934`; TGA joins at
`0x5109a7`). Success returns without trying other formats.

The general branch finds the last slash/backslash (`0x5109ac..0x5109dd`).
A literal `\Desktop\` substring skips resource attempts and enters the
fallback-texture section (`0x5109dd..0x5109ed`). Otherwise:

1. If a directory separator exists, format `dds\<basename>` using descriptor
   `+0x7c` and try DDS (`0x5109f5..0x510a20`).
2. Try the original name as DDS (`0x510a39`).
3. Try the original name as TGA (`0x510a53`).
4. Try the original name as JPG (`0x510a6c`).

Each nonnull result branches to `0x510c04`; all-null falls through `0x510a7e`
to engine fallback textures, with failure marker `0x20000` at `0x510bfd`.
Therefore an archive hit in the **earlier DDS-basename attempt** can beat a
loose hit for the original-name TGA attempt. Loose-first applies within each
attempt; it does not reorder this caller's attempts. Do not model these
fallbacks as global namespace collapse. Baking should report the selected
attempt and fail unresolved source inputs explicitly instead of substituting an
engine fallback texture silently.

Wrappers `0x4f52a0`, `0x4f75f0`, `0x4f6040` construct extension lists `pck dds`,
`tga`, `jpg`; their calls to `0x505e00` are at `0x4f534d`, `0x4f7680`,
`0x4f60ed`, each with user-directory flag zero. They read through `0x505f40`
and close through `0x5049a0`. Import `0x550378` is
`D3DXGetImageInfoFromFileInMemory`, called at `0x4f5416` in the DDS wrapper.
These observations qualify this dispatcher and table-backed branch, not a
census of every UI/video/procedural texture route.

## Effect reader, ABI and safety limits

`0x4db324..0x4db33e` obtains a profile string from
`(*(0x5aaf94)+0x18)->+0x38`, reads the effect name from resource object `+4`,
and formats `shader\%s\%s` (`0x58fbf0`). String capacity `+0x14` selects
inline storage below 16, otherwise a heap pointer. The reader accepts `fb`
(`0x58fc00`) and calls `0x505e00` with zero user-directory flag at `0x4db3bf`.
After read/close (`0x4db3da/0x4db3ea`), a missing result destroys the resource
and returns zero (`0x4db448..0x4db46b`), without a namespace retry.
`D3DXCreateEffect` is the import at `0x550330`, called at `0x4db49a` with the
buffer and size global `0x5ab3ec`. The code which selects the active profile
string is not traced here; do not infer profile selection merely from the
presence of archived effects.

Body/scene loaders take the ID in ECX and use plain `ret`; their name getters
return a string object in EAX and pop three stack arguments (`ret 0xc`).
Body registration uses ECX = manager and one string-object stack argument,
returns ID in EAX (`ret 4`); its setter copies the name into manager-owned
memory (`ret 8`). Temporary name strings and buffer owners are cleaned up on
the reviewed failure paths. Several complete loader windows have SEH frames;
this work does not qualify their exception handlers or arbitrary reentry.
The shared read-size globals, texture flag global `0x62dd38`, manager-table
reallocation and allocator callbacks preclude assuming thread safety or stable
borrowed pointers. No hook/displaced span, flag preservation contract, or
cross-thread injection is proposed.

## Reproduction and remaining gates

Run from the repository root (host Python with Capstone):

```sh
python3 verification/probe/verify_fl_resource_callers.py --exe /mnt/c/X3FL-orig/X3FL.exe
```

The tracked verifier checks whole-image identity, the reviewed resolver
prerequisite, instruction boundaries/direct branches, exact operands, strings,
descriptor pointers, category dispatch and D3DX imports. Semantic mutation
checks bypass image identity so they must fail the relevant witness; a separate
identity mutation verifies rejection of a different image. Raw disassembly and
JSON stay ignored under `verification/results/fl-port/resource-callers/`.
Measured result: **277 instruction, 26 string, 6 descriptor, 3 dispatch and
2 import witnesses**, with **25 negative checks**; 18 windows contain 2,198
decoded instructions. The local `check.py` producer also checks output-path
refusal, syntax, whitespace and note links; `check.json` records exit 0 and
0.312489 seconds for the analyzer on this host. These are static witnesses
supporting this interpretation, not an engine execution or filesystem resolver
simulator. There is no production/per-draw
cost; the verifier decodes only bounded windows and runs host mutations.

Independent review repeated the verifier (exit 0, 0.287358 s), checked
cleanup and registration/dispatch linkage against surrounding instructions, and
found no blocking issue within these stated boundaries.

For implementation: preserve each family policy and attempt order, classify
body/scene payloads by magic, keep exact mounted keys, and log selected source
provenance. Still unresolved: localized ties in the shared resolver; malformed
numeric-name fallbacks; full packed-payload/parser semantics; map/sector and
script background selection; active effect-profile selection; uncommon texture
routes and device/decode failure behavior. No GPU, native Windows, or CrossOver
runtime behavior has been tested by this offline task.

## Fog-tooling follow-up: explicit texture suffix dataflow

The fog consumer needed to establish whether an explicit `.tga`/`.jpg` is
removed before the first wrapper request. It is **retained**. The TGA wrapper
copies the supplied C string unchanged into its path string at
`0x4f765d/0x4f765e/0x4f7662`, passes that object at `0x4f767c/0x4f767f`, and
calls `0x505e00` at `0x4f7680`. That function forwards the path to `0x504b70`
at `0x505e0f/0x505e13` without modifying it.

The complete relevant resolver dataflow preserves the filename suffix:

- The loose branch loads the supplied path from `[ebp+8]` at `0x504d8c`.
  Helper `0x507a40`, called at `0x504d9a`, searches backward only for the two
  separator characters `/\\` at `0x590e1c`, using `0x507a6f/0x507a74`.
  `0x504e00..0x504e18` copies the substring after that separator, unchanged,
  into string object `[ebp-0xc4]`. That object is the rank helper's EDX input
  at `0x505021/0x50502a`; this is a directory split, not a suffix split.
- The archive branch obtains the **original** path object at `0x505458`,
  its C string at `0x50545b`, and a copy at `0x505464`. The loop at
  `0x505476..0x505494` uppercases and changes `/` to `\\` only. The copied
  path constructs `[ebp-0x78]` at `0x5054c4/0x5054c8`, which is passed as
  the rank helper's EDX at `0x5054ed/0x5054f3`.
- Rank helper `0x504a70` constructs that supplied name plus literal `.`
  (`0x58c204`, push at `0x504aa6`) and the accepted extension record
  (`0x504ab5/0x504ac4`), comparing the complete candidate at `0x504ae0`.
  String helper `0x4748f0` reserves the combined length, appends the original
  string through `0x4746b0` at `0x4749b2`, then the literal C string through
  `0x474580` at `0x4749d2`. `0x507b80` appends the extension string through
  `0x4746b0` at `0x507b9c` and copies the resulting string to its return object.

Thus a dispatcher input `environments\\paint.tga` first asks the TGA wrapper
for `environments\\paint.tga.tga`. Only after a null wrapper result does the
dispatcher zero the character four bytes before the original end at
`0x51092f`, reached from the TGA branch via `0x5109a7`, and recurse at
`0x510934`. This yields the suffixless DDS-basename/original-format attempts
described above. Do not silently strip arbitrary extensions in the resource
index or before this first attempt. The fog synthetic test includes a
double-suffix selected resource to distinguish these policies.

The retained [fog producer](../../../verification/results/fl-port/tooling/fog/reproduce.py)
checks image identity and exact instructions along these chains, including the
string helpers, with the two literal strings. This is static selection evidence;
it does not qualify D3DX decoder failure/retry semantics. A missing request may
advance to the next attempt; an offline selected-payload read/unpack/decoder
failure cannot be treated as proof of the engine wrapper returning null.

Material parameter to texture-registration flags is still not reconstructed.
The known table-backed path can supply `textures/<name>` or raw `<name>`;
font-scale/index variants also need their own caller qualification. The current
fog consumer accepts a directory-bearing material's DDS-basename winner only
after both possible explicit-suffix requests are absent. It refuses cases that
need an original-name decision instead of assuming the raw-name flag. Direct
explicit recipe requests retain the full dispatcher attempt sequence. This is
an unresolved integration boundary, not a permanent reduction of FL texture
support; the missing material registration/context path remains required.

## Review follow-up: material registration and stateful texture indices

Further targeted tracing supersedes the earlier assumption that a shared
DDS-basename path alone qualifies a material texture. The direct dispatcher
suffix contract above remains valid, but material registration occurs before it.

The MATERIAL6 text reader stores the file flags into material `+0x28` at
`0x49e10d/0x49e110` (its destination pointer was initialized to temporary base
`0x62a7d8 + 0x28` at `0x49df9a`). Flag `0x02000000` enters shader-material
parameter parsing through `0x489160` at `0x49e181`. Parameter names are read at
`0x4892c9`, type at `0x4892da`; the type-8 dispatch at `0x4892ec` reaches the
string-value read at `0x48a38c` and constructor `0x488f40` at `0x48a3a8`.
That constructor classifies the parameter name with `0x4daa30` at `0x488f72`;
`t_DiffuseTexture` maps to ID 1 (`0x4dacd1..0x4dace2`). It passes the ID, name
and value into `0x4daf90` at `0x48910e`, storing the returned index at parameter
`+0x20` (`0x489126`). Both its ID-1 dispatch and name-based diffuse branch call
texture registration `0x511ff0` with EDX zero (`0x4db21e/0x4db22a` and
`0x4db12b/0x4db137`).

Registration searches for the last literal dot through `0x4cd110`, which tests
`.` at `0x4cd134`. When the dot is exactly four characters before the end
(`0x51209a/0x51209d`), it copies the prefix and recursively registers it
(`0x5120a1..0x5120be`). Therefore ordinary material `.../paint.tga` registers
`.../paint`; this is an upstream registration rule, not permission to strip
extensions on direct resource requests. The rule applies to any final
three-character extension and repeats recursively.

Registration searches the existing texture-table names at
`0x512146..0x51219f`; a match returns that index at `0x512238`. A new name
increments the signed 16-bit dynamic count at `0x5121ae`, and stores the name at
index `base_count + dynamic_count - 1` (`0x5121f0..0x5121ff`). The base count is
copied from the loaded Materials count at `0x511cc1/0x511cd1`; dynamic count is
zeroed only at initialization (`0x511cca`) on this traced path. The selected
clean FL `addon2/types/Materials.pck` from `addon2/04.cat` declares **1,239**
rows. That initial count does **not** bound subsequent process registrations.

When material parameters are bound, ID 1 takes the index from parameter `+0x20`
at `0x4e1539`, and applies material `+0x28` flags through `0x512280` at
`0x4e1567..0x4e156f`. The setter preserves the old entry's `0x20000000` bit and
replaces the remaining bits (`0x5122b5..0x5122c0`); predefined Materials entries
also OR in their masked base flags (`0x5122c3..0x5122dc`). Thus raw-name flag
`0x10000000` and scale-sensitive flag `0x10000` have concrete sources rather
than an assumed universal setting.

The loader uses the registered index directly (`0x5113c2`). Its scale branch
adds 10000 only when descriptor state `G+0x774 > 1` **and** entry flag `0x10000`
is set (`0x5115c0..0x5115d1`). Independently, any already-high index at least
10000 takes the `%s_l` branch (`0x5115e7..0x511602`). The raw/prefixed name choice
then follows `0x51160d..0x511627`. Callers `0x5123f2` and `0x5124dc` forward the
index unchanged; the loader's failure return at `0x5116b0` does not retry the
unsuffixed name. Ordinary fog flags `0x02000000` do not trigger the scale-based
addition, but this does not prove that their dynamic indices stay below 10000.
The incoming index is not reduced by 10000 before lookup: `0x5113d6/0x5113d9`
form its `index * 16` record address, retained at `[esp+0x14]`. Flags come from
that record at `0x511496`; `0x5115dc/0x5115e0` retrieve the same original
record's name. The conditional addition changes ESI only, controlling its suffix.

Consequently a static subset of fog assets cannot establish a universal native
winner: process registration order/count, effective entry flags and scale state
can change the dispatched name. The clean installation has no indexed
`dds/*_l` stems, which makes low/high-index alternatives materially different;
it is not evidence that the engine always selects the low-index alternative.
No canonical-detail preference may be relabelled as a qualified native winner.
A native-winner assertion still requires sufficient dispatched-name/state evidence
or an explicit ambiguity refusal. The separately ratified
[recipe-normal artistic policy](../../architecture/farnhams-legacy-fog-texture-context.md)
uses registration suffix removal followed by its declared DDS request; it does
not assert a native winner or infer a runtime index. Material ordinals retained
by the offline tool identify entries within a selected body, not texture-table
registration IDs.
