# Native geometry frame leases

The ownership layer provides bounded, opaque frame and lease handles for a deferred renderer. Acquisition receives the actual live application VB/IB getter references and copies the original finite-position and index requests, including their owner generation. A lease takes independent native buffer references and CPU sidecar references. It never retains an application wrapper or logical parent reference.

`begin_geometry_frame` admits one active frame per recognized, healthy finite-evidence device. Beginning another frame without ending the first fails; there is no silent eviction. `acquire_geometry_lease` requires the same logical parent, exact indexedness/IB presence, known original generation/revisions, qualified native endpoints and successful finite/index evidence. Both allocations must pass before either native reference is retained. `inspect_geometry_lease` repeats the immutable requests against held native allocations, even when application wrappers no longer exist. Only S_OK/status S_OK exposes borrowed native pointers. Content refusal returns S_FALSE with null pointers; stale handles return E_INVALIDARG. The renderer must separately validate primitive ranges, declared min/count/base, shader semantics, scene/query state and all other replay prerequisites.

A currently live canonical wrapper must still have the original Lock/Unlock forwarding slots, parent, kind and native identity. No saved dead wrapper is dereferenced, and inspection never recreates one. Native AddRef/Release are additionally checked against the pinned Preview D3D9 module: VB RVAs 0x1950/0x19d0, IB 0x2430/0x24b0. The existing managed-upload qualifier establishes the exact module hash/imports and remaining buffer endpoints. A lease stores the certified Release entrypoint so its own acquired reference can be balanced even if a later foreign vtable replacement causes inspection to refuse. It never calls a foreign Release slot during cleanup. Foreign code patches, corrupted lifetime and completed invisible native writes remain outside the established contract.

There are fixed process tables for 64 frames and 8,192 leases, with at most 4,096 leases per frame. A process-wide 512 MiB retained-native-byte reservation counts each lease's full VB plus optional IB size; repeated leases for the same allocation are deliberately charged again. These are admission limits, not newly allocated GPU memory. Storage is fixed; there is no allocation on the frame/lease path and no silent truncation. Capacity refusal clears the output handle and leaves existing leases unchanged. The caller must reject or poison its motion batch as appropriate rather than dropping an observation silently.

Frame and lease serials are globally monotonic, nonzero and never reused; counter exhaustion refuses admission. Reset attempts, device loss and final logical device teardown invalidate the frame lookup before detaching references. Cleanup uses small fixed stack chunks and releases native references outside the global ownership registry, before backend Reset or final backend teardown. Detached native references remain charged against the global count and byte limits until native callbacks and CPU reference cleanup finish, so another device cannot over-admit against pending retirement. Per-lease release and end-of-frame also invalidate handles before releasing references. A permanent finite-evidence failure immediately makes inspection ineligible; its bounded native references remain until ordinary frame cleanup or lifecycle retirement. Borrowed pointers may not outlive release/end/reset/loss/teardown, and callers must serialize those events with all uploads and replay use.

All new lease APIs preserve incoming x87 environment/register payload, MXCSR and LastError using the existing verified ownership guard. They issue no draws, extra buffer mappings or GPU readbacks. Holding native references preserves allocation lifetime but does not freeze bytes: a pending, ambiguous or newer observed revision prevents replay under an older lease.

## Focused verification

`verification/probe/run_geometry_lease.py` builds the actual ownership, finite-evidence, native-contract and execution-state modules. It checks source/native-module hashes before and after compilation and execution, executable immutability, a unique terminal PASS and the exact CHECK count. Its no-game guard refuses to run while X3AP is active. The final suite contains 319 checks. Raw reports and provenance live under `verification/results/geometry-lease*`.

The fixture performs an actual indexed native draw after releasing both application buffer wrappers, reads the backbuffer solely inside the fixture and verifies its white center pixel. It covers wrapper recreation, independent native reference increments, all-or-none cross-device/IB refusal, immutable generation/revision checks, changed VB/IB and pending uploads, single release and stale handles, Reset success/failure, loss, final logical device/factory teardown, slot reuse, full per-frame/global capacity and conservative byte limits. It also replaces current wrapper and native reference-count slots, verifies refusal and cached original Release cleanup, checks all returned CPU/native accounting, and preserves seeded live x87/MXCSR/LastError through the complete API sequence.

A native private-IUnknown destructor waits for another thread to query the ownership registry during final leased resource destruction. Its completion verifies that native reference release occurs outside that registry. A second deterministic callback at the exact global lease limit verifies that another device remains refused until the detached native reference has finished destruction. Production contains no fixture-only scheduling hook. These are standalone Preview tests; they do not enable or qualify live-game motion replay.
