* The flight check's rise-time half (equal `ship_rate_k` rise time at ×1 and ×10) is not measurable from the 500 ms debug rows; the steady value matched in Run 197 A and the user judged the handling right. A per-frame row behind a dedicated trace option would settle it if the feel is ever questioned.
* The native fixture defines its own helper (`publish()` only): the DLL helper's `LightCallBoundary`, MXCSR load, armed
  check and debug row are not executed natively; they are covered by the source, the x87 walk and the wiring test only.
* Key stop latch: not flown. The first flight with `debug = 1` (architecture note, "First flight") decides the cause,
  either interleaving or a stale or empty read, and whether the lone-key repeat exists. If it exists, starts need the
  §7.4 mirror. The latch's per-iteration cost while armed is inferred, not measured.
