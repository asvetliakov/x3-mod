# Engine effects: verification ledger

Feature: `X3M_ENGINE_EFFECTS=native|off|plumes` (unset = `native`), phase 1b of
[engine-effects-modern.md](../architecture/engine-effects-modern.md). Code: `src/proxy/engine_effects_patch.cpp`,
site header `src/proxy/engine_effects_sites.h`. `off` and `plumes` redirect both calls of the per-ship engine
effect routine `0x00414590` ([engine-effects.md](../reverse-engineering/engine-effects.md) §7). Site A is
`0x004147eb` `call 0x004148a0` (effect instance: emitter sprite and engine lens flare). Site B is `0x0041482c`
`call 0x00412d70` (Particles3 trail generator). Each call goes to a stub that tests the 16-bit class word
`obj+0x48`. For 7 (ship) it returns at once: `xor eax,eax; ret` for A, `xor eax,eax; ret 0x10` for B. Every other
class (missiles) jumps to the original callee. `native` leaves the engine's bytes. Install happens on the
backend-load path inside the `engine_patch` install window and is both or none: B is claimed only after A is live
and has been read back, and a failed B restores A.

**Windows (whole instructions, compared before any write).** A: `0x004147c4..0x004147f2`, 47 bytes:
`f78360020000004000007523 8b5508 6a00 6a00 8d4c2428 51 6a00 6a00 6a00 52 50 8b442430 50 6a00 e8b0000000 83c428`
(the `0x4000` guard, the ten pushes, the call and the caller's `add esp,0x28`). B: `0x004147ff..0x00414830`,
50 bytes:
`f78360020000002000007571 8b0d346f6000 f781fc00000000000040 745f 8b4d08 8d542420 52 8b542414 51 50 52 e83fe5ffff`
(the `0x2000` guard, the VideoD3DFlags bit-30 test, the four pushes and the call). A's five bytes lie inside the
aligned qword `0x004147e8` and are written with one `lock cmpxchg8b` (`write=atomic`). B's rel32 crosses
`0x00414830`, so it gets the plain copy (`write=plain`), which is safe only inside the install window.
