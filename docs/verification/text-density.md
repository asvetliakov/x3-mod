## Open

- First flight (`--ui-scale 1.25 --debug` at 5120x1440, `d = 2`, with `build/fonts/F` installed by
  `manage.py install`): expect `text_density setting=auto status=pending`, one
  `text_density_install density=2 scale=1.2500 status=patched reason=ok … rows=35/8/29 fonts=Tahoma26,Zekton52,-0,-0`
  (or `rows=pending` followed by `text_density_rows status=applied … flagged=35 unflagged=8 nofilter_cleared=29`
  when the Materials load comes after CreateDevice; the order between the two is not established statically),
  `text_density_font … status=scaled` for Tahoma 13 and the LARGE font (three opens per game load plus the native
  cockpit's), `text_density_shadow … status=built` for the GUI atlases the menus blit, `text_density_draw` rows for
  every distinct (function, src, dst). What the code cannot prove: that the 35 flagged rows are all the text
  targets and no other row receives text (the fonts are opened at `d` globally, so a text line into an unflagged
  row draws `d` times too large into a 1x texture with overlapping lines: a visible layout break the flight must
  catch and name by its `text_density_draw fn=text_line … dst_flagged=0` row; a blit of a *generated* unflagged
  source into a flagged row draws half size and is reported with `src_generated=1 handled=0`); that the engine's
  manager unlocks the shadowed source atlases as it does for its
  own blits; that the copy leaf accepts the atlas format (a refused pair would leave the shadow black: icons vanish
  in menus); the visual result of the `d/s` minification at 1.25 (bilinear, no mips) versus the old magnification;
  the memory of the 35 rows at 2x (103 MB of surfaces plus the shadows) on the user's card; and the one-off shadow
  build time (logged per source in `ms=`).
- `B3D_TexBltImage` (x3intro) is not intercepted; fonts inside catalogues are not seen by the loose-file check.
