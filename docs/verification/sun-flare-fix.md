# Lens-flare collector fix: verification ledger

Feature: `--sun-flare-fix on|off` / `X3M_SUN_FLARE_FIX`, `src/proxy/sun_flare_fix.cpp`, site header
`src/proxy/sun_flare_fix_sites.h`. The lens collector's horizontal off-screen test keeps only the low
32 bits of `W·tan(F/2)·z/2`, so on wide displays a far sun near the view centre is declared off-screen
([field-of-view.md](../reverse-engineering/field-of-view.md) §9, design §9.1 (a)). `on` claims
`SHRD EAX,EDX,16; CMP ECX,EAX` at `0x0047e391` through `engine_patch` and puts a 20-byte stub in front
of the tail; the stub saturates an overflowing bound to `0x7fffffff`. The DLL default is `off` (engine
bytes). The launcher sends `on` on every modded launch and sends nothing under `--vanilla`.

**Cost.** The stub adds at most five instructions (a compare, a not-taken branch and the indirect jump; two
moves on overflow) per TSuns lens source per view per frame. It runs no proxy code per frame (inferred from
the code). Arena use is about 52 B against the 4,824 B headroom that `test_game_phase_sites` models.

**Remaining limit.** The stub covers only the second FixMul. The first, `t1 = FixMul(tan, z/2)` at
`0x0047e36d..0x0047e37b`, still wraps when `tan(F/2) ≥ 2` (`F ≥ 126.9°`). The FOV remap cannot get there:
`--fov N` (game units 50..130) gives `F' = 2 atan(0.75 tan(N/2)) ≤ ~116°`, and the menu's 100 is `F = 100°`
under `--fov game`. Only script cameras can reach that range (inferred from §9.1).

**Not covered.** Native Windows execution: the source uses only documented Win32 (`VirtualProtect`,
`FlushInstructionCache`, `ReadProcessMemory`, `GetEnvironmentVariableW`, `WriteFile`) and cross-compiles,
but it has not been run on Windows. A thread executing the site during the write was not exercised; the
single aligned 8-byte store is the argument (inferred). Not flown: the in-game check is that the sun's
lens chain stays present near the view centre at 32:9 with the menu FOV at 100 (Run 81 A launch 1
lost it within about 30° of centre).
