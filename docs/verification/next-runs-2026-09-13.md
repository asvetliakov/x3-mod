# Controlled user run groups after the September 13 integration

Pending: the final reviewed build must be installed before these runs, including
the [review 31 reader and adjacency fixes](review-31-adjacency-reader.md).
Review 30's first install alone does not authorize fast-mode tests. The
orchestrator will record its commit and SHA-256 here and validate every command
with `--dry-run`. This expands handoff section 5; it is not a request to test
an unfinished build. The user launches the game; the agent never does.

From the repository root, use this prefix followed by the arguments below:

```sh
X3M_BOTTLE=X3 python3 verification/probe/wine_lock.py --holder user-game python3 tools/manage.py launch --bottle X3
```

The lock keeps fixtures out while the game runs. Close the game between runs.
The explicit environment and bottle argument select both X3's game directory
and runtime even if the parent shell had a different `X3M_BOTTLE` value.
Use the same save and graphics settings where possible, and allow the scene to
settle after loading. Report which run completed and any visible regression.

A verify pass must show the intended hooks enabled, meaningful nonzero
computed/verified work, zero faults and zero mismatches for outputs admitted
to the fast path. Classify fallbacks separately; an all-fallback or unhooked
run does not establish correctness or a performance benefit. The reader run
must exercise the cursor cases that motivated its fix when using the same
save. Adjacency fast acceptance applies only to the same build, bottle,
normalizer and admitted floating-point domain as its verify run. X3's generic
normalizer evidence does not authorize Steam's unresolved SSE2 competing-normal
cases; those must remain native fallbacks even when `fast` is requested.

## Analysis protocol

Copy the selected session log and its readbacks/dumps from the installed
capture directory into a new `/tmp/x3-bottleX3-run<N>/` directory before
analysis. Inspect filenames, timestamps and file sizes first; do not overwrite
an earlier snapshot. Copy only files belonging to that run, and distinguish
complete sessions from a still-running session. The capture directory is
reported by `tools/manage.py status` and the session's `capture_dir=` field.

Use bounded streaming analysis under `tools/analysis/` rather than reading a
large log whole. Record build provenance, flags, scene/save differences,
acceptance counters and phase timings in the verification document and update
`docs/status.md`. Keep raw logs, mesh dumps, textures and readbacks local and
untracked. Compare run 5 with the preserved `/tmp/x3-bottleX3-run16/` fixed-EV
baseline; if the scene differs, distinguish that from an exposure regression.

Separate diagnostic overhead and fixture microbenchmarks from game frame time
and uninstrumented load time. Verify-mode work is intentionally duplicated, so
its total load time does not predict fast-mode performance.
