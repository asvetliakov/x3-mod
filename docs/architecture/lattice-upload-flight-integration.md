## 1. Exact game seam and original dispatch

Reuse `docs/reverse-engineering/mesh-buffer-rewrite.md`, final CloneMesh interval. Claim **all five bytes `[0x004bcc2b,0x004bcc30)` = `8b 41 30 ff d0`**, `mov eax,[ecx+0x30]; call eax`, through `engine_patch::Site`/`claim`, with the documented surrounding context and EXE validation. Do not use `claim_call` (this is not an E8 rel32) and do not patch the two-byte call alone. The span fits one aligned eight-byte word, so the existing atomic write path applies. Preserve arena capacity checks and rollback-failure reporting.

Install during `capture.cpp::initialize_log`'s established backend-load install window, before a factory/device is exposed; first Present closes that window. Never claim or reinstall from F8 or device recreation. An off/unarmed adapter must run the ordinary displaced tail exactly once. A successfully installed patch/module has process lifetime as with existing pinned engine patches; device retirement disables its observer route, not its executable storage. Rollback restores all five original bytes only in the existing safe install/rollback or quiescent test window. Do not promise live concurrent unpatching.

At seam entry the five native stack arguments already exist: `(this, options, declaration, device, out)`. The original is stdcall, consumes20 bytes, returns HRESULT in EAX, and resumes at `0x004bcc30`; EBX/EBP/ESI are live nonvolatiles. The adapter must capture the **dynamic original public COM target from `[ECX+0x30]` before any observer call**, and forward exactly that target and those argument bits once. It must not hardcode a D3DX implementation address.

**Required delta:** current `clone_upload_abi.cpp::x3m_clone_original` re-reads `args.source->CloneMesh` after observer preparation. That is not equivalent to the displaced MOV/CALL if a callback changes the vtable/slot. Extend the qualified ABI shell with an explicit saved-target engine-entry path, or an equally demonstrated mechanism; keep the existing manual API working. Carry the saved pointer into the original call rather than checking it and re-reading later. Native/C++ unwind, incoming/outgoing x87/MXCSR/LastError, four-byte incoming stack and original result must still follow the accepted shell. A plain cdecl call to the current manual function plus guessed stack cleanup is not accepted without emitted-code/fixture proof.

Supply the fixed six-element target declaration already validated by the state selector. Require **S_OK**, not generic SUCCEEDED; S_FALSE is an unavailable/busy diagnostic. Do not wait for first Present or first matching draw, which may miss the load.

The coordinator owns Store storage until exact-S_OK disarm. `arm_clone_upload` retains one **wrapper device reference** (`upload_arm_core` increments `d->refs`), so merely waiting for `device_destroy` creates a pin cycle. If a clone scope is active, `disarm_clone_upload` returns S_FALSE: retain Store and pin, mark deferred retirement, and complete cleanup after that scope's normal/abort exit at a safe boundary. Do not spin, wait on the same callback stack, force-clear the Store, invent zero references, or destroy storage merely because teardown was requested. This cooperation is a lifecycle implementation requirement, not supplied by the existing manual observer. Existing guarded getter/device-retirement behavior must remain intact.

One armed device is the explicit coverage contract. A second concurrent device logs busy/unavailable and forwards unchanged. After the old device quiesces and disarms, an eligible recreated device may reuse the same reset Store and arm before it is returned to the application; the game patch remains installed. Do not migrate old records or change the active owner while a scope/copy is in flight.

## 3. Reset, shutdown and coverage

The ownership observer already invalidates/wipes retained records on Reset and prevents native Reset start during the guarded copy. Preserve that ordering. Capture's Reset path must also cancel any pending F8 payload packet. Keep the Store/device arm on an ordinary Reset; a failed Reset/loss leaves copies unavailable and a successful Reset starts a new ownership generation with no valid retained payload. MANAGED resources may survive without another upload, so **post-Reset no-payload is an expected refusal**. Do not resurrect pre-Reset bytes or perform a compensating readback. Device recreation uses the teardown/rearm path above.

No COM release, wait or Store teardown under DllMain loader lock. Ordinary last-device cleanup must disarm first; process termination can rely on OS reclamation after disabling entry, consistent with process-lifetime pinned patch storage. Any explicit module teardown path must be quiescent and already disarmed before code/storage can disappear. The hook fixture must cover restoration; do not add a user-facing hot unload facility.

**Current Store behavior is already stricter than an overwrite cache.** `clone_upload_core.h::begin` sees an already valid matching shape or prior duplicate, wipes that slot, sets `duplicate_[slot]`, and returns Busy. It remains poisoned until explicit reset/disarm. Preserve this exact no-first/no-last-match-wins rule. Two shapes are candidate filters, not model/instance identities. If another matching model/clone appears, the relevant F8 payload is refused even if state selection succeeds. Do not automatically clear/rearm on the first duplicate, F8, or an ordinary scene change, and do not infer a ring expansion from low capture coverage. Record slot refusal and publication counts so the first user result can distinguish a safe coverage miss from corruption.

## 4. F8 attachment and file contract

Keep existing unique position/object/shader/draw selection, candidate64 limit, two selected draws and successful native submission requirements. At `Capture::effective`, acquire the **actual current stream0 VB and IB together**, retain their getter references within the existing `lattice_query_depth` guard, validate the same declaration/ranges, and call an ownership helper that authenticates both allocation IDs, revisions, owner and generation against the Store. Getter identities or requested descriptors alone are insufficient.

Prefer a small paired CPU-copy result API extending `copy_clone_upload`: under one registry guard, return the immutable published Record metadata and both payloads into the preallocated F8 packet. No COM callback between final guard and memcpy; no resource Lock. This avoids exporting Store internals or mixing metadata from separate guarded calls. If reusing the existing two per-buffer copies, the integration must prove the same record/invocation for both and erase/refuse the entire pair on either failure; no partial-valid pair. Guarded releases still occur before original game draw forwarding and preserve the existing observer's callback safety.

Producer Store memory is not the packet's ownership: copy admitted **published CPU bytes** into a bounded packet owned by the existing shared Capture pin. Never expose speculative staging. Allocate packet payload capacity at the explicit F8 edge, not during a selected draw. Exact selected totals are VB387200+IB22704 and VB50680+IB5640 =466224 bytes. Keep separate resource-payload cap2MiB and existing state/shader limits; log CPU copy timing separately. At most two selected pair copies per armed F8 frame; this is bounded diagnostic draw-time **CPU memcpy**, not zero per-draw diagnostic work.

Use a versioned packet with per-record `producer_payload_valid`, upload invocation/allocation/revision/owner/generation, byte sizes/formats, `binding_revision_match_at_observation`, and precise refusal. Keep `draw_input_coherence=unqualified`, texture payload not attempted and later-writer status unknown. Neither callback bookends nor matching bytes upgrades those claims. Original native draw must still execute once with unchanged arguments/result. A Reset, duplicate selector, failed submission or incomplete pair makes the packet's current-draw attachment invalid; the collector may retain refusal metadata but must never load partial bytes as valid geometry.

At Present, write one CPU-only binary payload plus JSON metadata through bounded staging files; finalize metadata last after payload size/hash succeeds. Hash only admitted published packet bytes, outside upload/selected-draw callbacks. On publication failure keep a precise invalid/refused state, not a successful filename. Extend `snapshot_x3_run.py` using its existing path/session/size checks, with explicit new basenames and caps. The validator checks exact lengths/INDEX16 ranges/record linkage and refusal semantics; raw source reconstruction must never substitute for absent runtime bytes. No COM or native pointer crosses into file serialization.

## Cost, native behavior and unresolved risks

Default off: no Store, no byte retention, no creation-policy changes, no installed clone hook. On: one startup allocation, two bounded upload copies plus failure wipes per attempted selected revision, loading-time getter/metadata work for clone filtering, and at most466224 admitted bytes copied at a complete F8 observation. Readable creation affects all eligible MANAGED VB/IB on that factory and can change placement/performance; measure loading and report fallback counts. Global shader/history/AA settings are unchanged by the diagnostic itself; conflicting feature settings must be surfaced before launch.

The mechanism uses exact validated game instructions plus public COM/D3D9 identity/creation/mapping semantics; no Wine-private layout/export or D3DX DLL hash becomes a runtime prerequisite. Native Windows runtime, arbitrary native bypass and inherited callback-SEH recovery remain limited exactly as in §31. Fail closed for unobserved producer patterns. Remaining implementation risks are saved-target ABI extension, distinguishing/releasing the observer pin without recursive final-release errors, guarded packet reference cleanup, and insufficient two-slot coverage. These are the checkpoint acceptance targets, not reasons to expand the instrumentation framework before the first scoped capture.
